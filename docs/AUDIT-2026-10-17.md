# Codebase audit — 2026-10-17

**Scope.** `cc4480/secscan-redteam` @ `main` (working record: runner, harness plugin,
auth gate, llm router, desktop bundle, packaging configs, docs).
**Method.** Field-first: a live installed app was driven through real engagements, every
failure was captured from its audit log, then the same call path was traced into this
source tree. Findings are therefore reproducible, not speculative.

---

## 1. What the field run proved was broken (and is now fixed here)

Seven defects blocked "install it and it just works". All were reproduced on a live
install (`SecScan RedTeam` 44.0.0 / runner 0.22.0) before being fixed in source.

| # | Defect | Where it hurt | Source fix |
|---|---|---|---|
| 1 | **ffuf wordlist was a hardcoded dev path** (`C:\Users\Cho-zen\...`) | every ffuf run failed on any other machine | `runner/src/xtool/wordlist.ts` (new resolver) + `dispatch/xtool.ts`; bundled `runner/assets/wordlists/common.txt` |
| 2 | **ffuf argv had no `FUZZ` keyword** | `Keyword FUZZ defined, but not found in URL` — run wasted | `xtool/registry.ts` `buildXToolArgv` (path → `/FUZZ`, vhosts → `-H Host: FUZZ`) |
| 3 | **nmap required raw-socket privilege** (all profiles `-sS`) | unprivileged Windows runner could not map a single port | `nmap/privilege.ts` (new) + `nmap/executor.ts` one-shot connect-scan fallback |
| 4 | **nmap prereq only probed for a path** | "present" then `STATUS_DLL_NOT_FOUND` mid-engagement | `nmap/prereq.ts` now runs `nmap --version` |
| 5 | **`start` ignored `--engagements-dir`** | artifacts written to cwd; `get_engagement` said `artifacts:false`, `get_feed` said "unknown engagement" | `cli/commands.ts` passes `engagementsDir` into `runEngagement` |
| 6 | **`@seclayer/mcp` crashed on async scans** (`toUpperCase` on null) | every `seclayer_scan` returned an error instead of a report; same crash in the CI gate | patched in the package install (server repo: `mcp-server/` — port the same two changes: poll until `status==="complete"`, guard null severity) |
| 7 | **Windows tool prerequisites undocumented/unchecked** (Npcap has no silent install in the free build; nmap x86 needs the VC++ 2015-2022 runtime) | two separate hour-class debugging detours | covered by the new readiness layer + docs below |

**Evidence trail:** `nmap exited null ... spawn nmap ENOENT`; `ffuf not found`; `Keyword FUZZ
defined, but not found in URL`; `Cannot read properties of undefined (reading
'toUpperCase')`; `artifacts:false` while `report.md` existed on disk; `msf_exec` denied as
"exploit phase only" during recon.

## 2. New capability: `redteam-runner doctor`

`runner/src/tools/readiness.ts` — one honest answer to *"can this installation run an
engagement right now?"*

- **required:** nmap (executed, not merely located), a wordlist, `SECSCAN_MCP_TOKEN`,
  `DEEPSEEK_API_KEY`
- **optional but reported:** ffuf/gobuster/nikto/sqlmap/john, `SECLAYER_API_KEY`,
  msfrpcd (credentials configured? TCP reachable on `REDTEAM_MSFRPC_HOST:PORT`?)
- every non-ready item carries a `fix` string written for the operator, and the CLI
  renders it: `redteam-runner doctor [--json]` (exit 0 only when every required item is
  ready).

This is the hook the desktop app should render on first run — ideally with one-click
install of the bundled payloads (see §3).

Tests: `runner/test/readiness.test.ts` (12 assertions across wordlist precedence, FUZZ
argv, privilege signatures/rewrite, and report semantics).

## 3. "Everything connected in the exe" — packaging plan (desktop repo)

The engine is correct; the *distribution* is where readiness was lost. Required changes in
`cc4480/secscan-redteam-desktop`:

### 3.1 Bundle the tool payloads (no operator setup)
Ship under `resources/tools/` in the installer and have the supervisor export
`REDTEAM_TOOLS_DIR` into the runner child environment:

```
resources/tools/
  nmap/            nmap.exe + data files + msvcp140.dll, vcruntime140.dll, vcruntime140_1.dll
                   (app-local VC++ redistribution is licensed; avoids an installer step)
  ffuf/ffuf.exe
  wordlists/common.txt
```

The runner already resolves `REDTEAM_TOOLS_DIR/wordlists/common.txt` first. Bridge binaries
should resolve the same way (small follow-up: let each bridge prefer
`<REDTEAM_TOOLS_DIR>/<tool>/<tool>.exe` before PATH).

### 3.2 Do not require Npcap or elevation for the baseline
With the connect-scan fallback, nmap port/service mapping works **unprivileged and without
Npcap**. Treat SYN + `-O`/`-sU` and the Metasploit arm as *enhancements* offered when the
operator runs elevated; the default experience must not need a driver install.

### 3.3 Supervise `msfrpcd` like the runner console
The desktop main already starts the bundled engagement console and publishes its endpoint
token into `process.env`. Do the same for Metasploit when a Framework install is detected:
generate a random RPC password, start `msfrpcd -a 127.0.0.1 -p <free> -S`, and export
`REDTEAM_MSFRPC_*`. Kill it with the app. No logon task, no orphan ruby process.

### 3.4 Forward the Secure Vault into the engine environment
Today the vault reaches the Harness but **not** the engagement console child, which is why
live runs halted with `[runner] DEEPSEEK_API_KEY is not set` and why
`SECLAYER_API_KEY` was invisible to the stdio MCP server. The supervisor should forward a
fixed allow-list (`SECSCAN_MCP_TOKEN`, `DEEPSEEK_API_KEY`, `SECLAYER_API_KEY`,
`REDTEAM_SMB_*`, integrations) into every child it spawns, and never log the values.

### 3.5 First-run readiness panel
Render `doctor --json` in the welcome/setup flow: green checks, "Install tools" button that
copies/registers the bundled payloads, and the token fields the app already has. A new
install should reach a runnable engagement without a terminal.

### 3.6 Signing
Smart App Control blocks unsigned downloaded installers (documented in
`DESKTOP-BUILD-STATUS.md` §Round 5). An Authenticode certificate is a release requirement,
not a build one.

## 4. Correctness / safety backlog (P1)

1. **MSF is locked out of recon** — `msf_exec run` is exploit-phase-only, yet policy allows
   `auxiliary` modules. Read-only scanners (`auxiliary/scanner/*`) should be permitted
   during recon; that gives a second discovery path when nmap is absent.
2. **Scan-quota coordination** — `scan_url` is capped (5/hour) and the engine discovers the
   limit by failing. Ask `get_account` once, budget scans in the plan, surface remaining
   quota in the event feed.
3. **Action-cap defaults** — 60 exhausts a full battery before a probe (the source comment
   already admits this). When `--full-battery` is set and `--max-actions` is not, derive a
   floor from the selected battery size (e.g. items × 2) instead of halting half-answered.
4. **One config module for 59 `process.env` reads** — scattered reads make the readiness
   contract unenforceable and drift silently. Centralise into `runner/src/config.ts` with
   typed getters the doctor can reuse.
5. **Timeouts are magic numbers** — ffuf hard-codes 300s, xtool `${Math.max(60, Math.min(900,
   rps > 0 ? 300 : 300))}` collapses to 300. Make per-tool timeouts configurable and
   reported in the event log.
6. **Artifact-path regression test** — pin "engagement dir == configured dir" in a test so
   defect #5 cannot return.

## 5. Performance / developer-experience backlog (P2)

1. **No CI exists** — added `.github/workflows/ci.yml` (typecheck → build → dist-hash →
   tests on Node 22/24). This is the single highest-leverage change for "faster".
2. **Bridge boilerplate** — nmap/nuclei/xtool repeat the same spawn → timeout →
   privilege → parse shape. Extract a shared `bridges/run.ts`; keep per-bridge policy pure.
3. **Version drift** — repo runner is 0.22.0 while the shipped app vendors a different
   build; add a `sync-versions` script and assert in CI that `runner/package.json` and the
   desktop package set agree.
4. **Docs** — add a RUNBOOK for tool prerequisites (the Npcap/VC++ trap cost hours) and an
   ADR recording *why* connect-scan is the default.
5. **Static hygiene is healthy**: 232 source files, 3 TODO/FIXME, 1 `as any`, enforced
   300-line file budget — keep the budget test, it is doing real work.
