## A. Engagement engine — `secscan-redteam/runner`

### A1. Field-verified defects (each reproduced in a live run before being fixed)

| # | Change | Better because |
|---|---|---|
| 1 | Wordlist resolver + bundled `assets/wordlists/common.txt` (`xtool/wordlist.ts`, `dispatch/xtool.ts`, build copies assets) | A fresh install no longer depends on one developer's `C:\Users\Cho-zen\...` path. Resolution order is explicit (arg → `REDTEAM_WORDLIST` → tools dir → packaged asset → operator override), so content discovery works out of the box. A genuinely missing list now returns a setup message naming every path searched instead of a confusing failure. |
| 2 | ffuf argv always carries a `FUZZ` keyword (`xtool/registry.ts`) | Every ffuf run now actually fuzzes. Before, the tool errored with `Keyword FUZZ defined, but not found in URL` — wasted credits and dead runs. Path profiles get `/FUZZ`, vhost discovery gets `Host: FUZZ`; a flag-like target still passes through verbatim, so the "a value can never become a flag" guard survives. |
| 3 | nmap connect-scan fallback (`nmap/privilege.ts`, `nmap/executor.ts`) | An unprivileged runner (no Npcap, no Administrator) still produces a port map instead of failing every host item with "raw sockets require privilege". SYN scans are still used when privileged; the result notes the fallback. Host coverage no longer depends on elevation. |
| 4 | nmap prerequisite runs `nmap --version` (`nmap/prereq.ts`) | A present-but-unrunnable nmap (missing VC++ runtime, missing driver) is detected at readiness instead of mid-engagement. This exact failure cost a full run. |
| 5 | `start` honours `--engagements-dir` (`cli/commands.ts`) | Engagement artifacts land where the console reads them. Before, a completed run wrote to the process cwd, so the console reported `artifacts:false` and "unknown engagement" for a run that had finished. |

### A2. Readiness

| # | Change | Better because |
|---|---|---|
| 6 | `redteam-runner doctor` (`tools/readiness.ts`, `cli/commands.ts`, `cli/args.ts`) | One command answers "can this installation actually run an engagement?" — nmap executed (not just located), wordlist resolved, msfrpcd reachable (1 s TCP), required credentials present; every gap carries the operator-facing fix. Exit code is 0 only when required items pass, so the desktop app can gate first run on it. |
| 7 | Optional backends reported, never required (`tools/readiness.ts`) | The Windows PC-agent channel and browser/CDP driver show as `not-configured` without blocking a run — coverage channels are discoverable instead of invisible. |

### A3. Event model (R2 — ported from AlterEgo, with its G2 defect fixed)

| # | Change | Better because |
|---|---|---|
| 8 | Recursive secret redaction (`events/redact.ts`, wired into `EventLog.writeEvent`) | No credential can reach `events.jsonl`: secret-named keys are redacted at any depth, and known secret values are masked anywhere in a string — including inside a free-form `result`. AlterEgo's version redacted top-level keys only and wrote nested secrets in cleartext; this port closes that class. |
| 9 | `EngagementEvent.causedBy` causality (`types.ts`) | Every action can name the action that caused it. Proof bundles and audit reviews can show "this observation ← that probe" mechanically instead of by narrative. |
| 10 | Pure projections (`events/projections.ts`) | Tool stats, actor timeline, approval timeline, findings, causal chain and a dangling-cause integrity check are computed once from the stream, are testable, and are reusable by report, console and compliance output. |
| 11 | Report "Tool activity" section (`report/activity.ts`, `report/phase.ts`) | The report now states what actually executed — per-action counts, ATT&CK ids, seq ranges — plus the operator-decision timeline and a causality-integrity line. Runner-computed, never model narrative. |

### A4. Operator controls (R3/R7/R4/R6)

| # | Change | Better because |
|---|---|---|
| 12 | Tool lifecycle hooks (`hooks/index.ts`, `dispatch/policy-gate.ts`) | Engagement-specific policy can be injected without touching the safety core: PreToolUse may allow, deny or modify arguments; PostToolUse may replace a result (e.g. scrub it). Timeouts fail closed, and every hook evaluation becomes its own audit event — no silent decision. |
| 13 | Operator policy rules (`policy/rules.ts`) | Client constraints ("never touch the payment path", "only these hosts") become data instead of code: JSON allow/deny, deny wins, optional allow-list default-deny, glob matching, enforced before any packet. |
| 14 | Risk profiles + trajectory arbitration (`safety/risk.ts`) | Adds per-tool risk the tier system cannot express: blast radius, recoverability 0–10, side effects, compensating action, sensitivity tags; a trajectory score/tier/rationale, ranking, and a rollback plan. Unknown tools resolve to a fail-closed profile and never throw (AlterEgo's G1 defect). |
| 15 | Opt-in pairing (`ui/pairing.ts`) | A remote operator can be authenticated with a 6-digit single-use code (30-min TTL, 5-guess lockout, constant-time compare) instead of pasting a 256-bit bearer token into chat or history. Opt-in via `REDTEAM_PAIRING=1`; the existing token path is untouched for local use. |

### A5. Backend contracts (R1/R5)

| # | Change | Better because |
|---|---|---|
| 16 | Windows PC-agent channel (`host-exec/pc-agent.ts`) | Defines the authenticated, allow-listed execution channel for a Windows target with no SMB/WinRM/SSH — the exact gap that halted a live engagement. Configuration is explicit (URL + token), the tool set is closed, the MCP handshake is typed. Execution against a real agent still requires an on-host smoke test (documented as a contract, not claimed verified). |
| 17 | Browser/CDP driver (`browser/cdp.ts`) | Defines authenticated browser automation — snapshot, navigate, fill, eval — over an injected CDP transport. This is what unlocks cross-account IDOR, business-logic and JWT coverage, which `authHeader` alone cannot reach. Transport and on-host verification remain explicit follow-ups. |

## D. Machine and tooling changes (why the build is now reproducible)

| # | Change | Better because |
|---|---|---|
| 29 | Portable **MinGit 2.56** installed | Version control, diffs and pushes work without an administrator install; the desktop build also shells out to `git`, which previously failed with `spawnSync git ENOENT`. |
| 30 | Portable **Node 24.22 + npm 11.19** toolchain | Real builds/tests of the runner instead of guessing: 746 tests, typecheck, dist-hash. |
| 31 | **VS Build Tools 2022** (+ VC++ x64/x86, Windows SDK) | The desktop packaging preflight requires `vswhere` and MSVC for the native module and NSIS; nothing was installed, so packaging refused to start. |
| 32 | `LongPathsEnabled=1` | The packaged Python's `lxml` extension sits 261 characters deep in the build tree and failed to load. Long paths plus a short build root make the packaged-runtime smoke pass. |
| 33 | Desktop clone relocated to **`C:\dsh-src`** (junction left at the old workspace path) | Windows' 260-character limit made the build fail in a deep workspace path; a physically short root is the reliable fix. The junction keeps the familiar path working. |
| 34 | Git identity + credential (Git Credential Manager) configured | Commits and pushes are non-interactive, so both repositories stay in sync with GitHub. |
